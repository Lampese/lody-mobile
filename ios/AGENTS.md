# Lody iOS

- This is an independent iOS-only UIKit client. pnpm builds the bundled cloud protocol assets; XcodeGen generates app, extension and verification targets; Swift Package Manager builds LodyKit and its native dependencies.
- First-party UI and state live in the Swift package `packages/LodyKit/Sources/LodyKit`; the application entry point is `App`, and extensions are in `Extensions`. Use Swift/UIKit or SwiftUI; do not add bridge packages. SwiftPM discovers LodyKit sources automatically. Run `pnpm prebuild` after changing app/extension source membership or shared extension references in `project.yml`; never edit the generated Xcode project by hand.
- Do not add Android implementations, fallback stubs, or Android build scripts.
- `apps/ios/Lody.xcodeproj`, `.generated` are generated. Persist app configuration in `apps/ios/App`, app/extension target definitions in `apps/ios/project.yml`, and package dependencies/resources in `packages/LodyKit/Package.swift`. Run `pnpm prebuild`.
- Keep normal Xcode signing enabled, including simulator validation. Do not use `CODE_SIGNING_ALLOWED=NO`.
- Cloud integration targets official Lody Cloud. Use browser-safe public protocol imports in `packages/cloud-runtime`; do not import Node-dependent `@lody/shared` or `@lody/loro-streams-rpc` root entries, absolute paths from another checkout, or private backend packages.
- Credentials belong in Keychain. Never copy desktop credentials, tokens, transcripts, or private service configuration into this repository.
- `LodyApplication` owns lifecycle and application coordinators. `AuthSession`, `CatalogSession` and `OutboxSession` own native state; feature controllers observe their projections. Keep protocol code in `packages/cloud-runtime` and generated wire types in `packages/lody-core` (`pnpm contract`).
- Shell pages use transparent headers and soft scroll edges. Native pages bind their scroll view through `LodyScrollEdges`.
- Preserve user edits. Before destructive revert/restore/rollback, inspect the working tree and obtain explicit confirmation.
- Verify with `pnpm check`, `pnpm bundle`, and an iOS simulator build when changing native code. Prefer behavioral checks over implementation snapshots.
- Do not nest ternary expressions. One `cond ? a : b` is fine; a `?` inside either branch is not. Map a closed set with a dictionary, and use `if` / `switch` for ordered or overlapping conditions. Optional chaining and `??` are not ternaries.

## UI baseline

- Apple HIG is the primary UI requirement. Chat references inform behavior only; preserve native conventions.
- Do not use green as the app accent. Diff additions use systemGreen, paired with systemRed deletions. Use UIKit semantic colors for native content, system blue for actions, and neutral system backgrounds. Preserve automatic dark mode and accessibility contrast adaptation.
- Preserve native navigation, safe areas, VoiceOver labels, and at least 44 pt touch targets. MVP acceptance uses the default text size; keep system text behavior but do not add special layouts or remount logic for oversized accessibility text.
- Reference Yohaku iOS for native UI boundaries. System grouped rows use `LodyGroupedList` / `UICollectionViewListCell` in LodyKit; navigation uses UIKit automatic scroll edges through the existing native stack. Register native collection views with UIKit directly; do not simulate native effects with decorative overlays.
- `LodyGroupedList` system-row pages default to flat rail rows; CreateSession and its pickers opt back into inset-grouped rows with `setGrouped(true)`.
- iPhone Home follows the shared mobile design system in `../design-system` (SwiftPM `LodyDesignSystem`: semantic tokens, Inter, Lucide icons). Layout: workspace capsule leading; search (iOS 26 `integratedButton` placed via `searchBarPlacementBarButtonItem` with toolbar integration off, otherwise UIKit drops it to the bottom edge under the tab bar; hides the capsule while active) then the view menu trailing; `HomeTabBar` (`Shell/HomeTabs.swift`: a standalone system `UITabBar` for the Liquid Glass draggable selection, labelled Chats / Projects / Settings, plus a separate `.glass()` new-chat button) shared on the primary navigation host so Liquid Glass selection persists across tab changes; hidden on pushed pages. `HomeController.selectTab` slides cached roots horizontally in tab order via `HomeTabNavigationDelegate` (reversed for RTL, disabled for Reduce Motion), and queues the latest selection during a transition. The view menu also scopes Chats to My tasks (session `userId` is the signed-in user; `HomeScope`, UserDefaults, default team; search is unscoped). Chats groups by the view menu's single choice (`Sessions/HomeGrouping`, UserDefaults, default time) via `InboxSections.home`: time buckets, projects by latest activity (rows drop the project from line 2), or status (`HomeStatusGroup`, web `lib/home-now.ts` order: needs you / just finished / running / open PRs / idle; idle folds after 20). Within a group chats are newest activity first; there is no separate sort. Connection trouble is not in the capsule: `Sessions/HomeSyncPill` uses the navigation title view while the workspace name animates down to its logo to make room (web `MobileConnectionStatus`: syncing spinner, offline dot, "Connected" for 1.2 s, no touches). Projects lists `InboxSections.projectIndex` (`Projects/ProjectsListController`). Long-press Settings opens Debug. iPad keeps the split, sidebar, gear and `InboxPadBar`.
- `Sessions/ChatListView` renders these lists (outside search, a single native supplementary group header pins under the bar and is pushed off by the next header; a shared native blur backdrop extends from that label to the window top; a blurred base and stronger upper layer avoid mixing sharp text back through the gradient, with a dark-mode page tint and no separate navigation edge or second label; Android pins the same label over a page-colour fade) (and project pages) from `InboxSections` projections and emits the same `rowPress` / `rowAction` events as `LodyGroupedList`. Rows: status mark (web `SessionRowStatusIndicator`: alert, hand, `LodyWorkingGrid`, unread dot), title and compact age on line 1; an optional line 2 with repo / folder + project, branch and the PR mark trailing (a PR mark alone stays on line 1, before the age; open / draft PRs carry the web CI verdict badge); the status mark centres on the whole row. Opened chats nest one level under their opener (`SessionRows.treeRows`; a child hides a project that repeats its opener's). The opener row stays like any other (its own project / branch line); below it the family line `⌄ 7 opened chats` (`ChatRowContent.familyToggle`, count from `LodyListRow.childCount`, full-width target, chevron at the opener's title edge, turning right when folded; `homeFoldedOpeners`, default unfolded) heads the family. Children read one size down (callout, 40 pt rows), keep the shared status column, and hang off one continuous 2 pt rail under the chevron (round end on the last child) with titles stepped in `childLevel`. A folded opener's status shows its family's most urgent. The view menu is a multi-select (`ChatRowDetails`, UserDefaults, default project + PR) of what line 2 shows; none leaves rows one line. New surfaces should adopt the design system; other pages keep the system baseline below until migrated. All copy goes through `Localizable.xcstrings` (en + zh-Hans).
- In the iPad sidebar, Home section heads are `lodyBand` bands inset with 12 pt side margins and rounded corners, because full-bleed bands clash with the inset sidebar rows.
- Conversation turns follow web's mobile session page: a user turn's first bubble carries its sender (`ChatRow.author`, from the session entry `userId` the runtime projects; `ChatAuthors.unknownSender` for older turns and local sends, resolved to the signed-in user), time and read state (seen check / sent circle / queued clock / sending), drawn as a right-aligned header (mark, time, name; web's order) with the sender's 36 pt avatar beside every bubble of the turn; other members show as Member until the member list is loaded. The agent's identity stays in the meta row after its answer (mark, model, time). `ChatReadingColumn.cellMargin` is 16 pt, web's mobile inset.
- The conversation's action bar (web `SessionInfoBar`) is a row of grouped Liquid Glass capsules above the composer, so the composer stays the only full-width shape (`Chat/ChatActionBar`: SwiftUI `ChatActionBarContent` in a `GlassEffectContainer`, hosted by `ChatActionBarView`, fed by composer state `actionBar` from `SessionController+InfoBar.actionBarState`; actions return as `bar:` ids through `onPreview`). Capsules: environment (computer with presence menu, browser preview and simulator from `resourceItems` — tap opens, menu copies / stops — and live sub-tasks with their count), context (PR number, else branch, else repository name without owner; CI trouble tints the glyph; the ±diff inside; menu: workspace changes, the native PR page, copy branch) and, pinned trailing, the top repository action as a neutral split capsule whose chevron `Menu` holds the rest. Colour is for status only so Send stays the one accent. It never scrolls: `ViewThatFits` takes the first stage that fits one line (labels capped at 140 pt, then the diff as a dot, then the environment folded into one icon with a `+n` badge and a menu of all), and only at very large text stacks the action on its own trailing row (`fittingHeight(width:)`). There are no quick replies; the bar stays while typing and hides in expanded editing. `Sessions/SessionInfoBar` ports `resolveSessionInfoBarGitHubActionIds` and web's prompts; prompt actions send as ordinary turns, only while still offered. Merge (after an action sheet of merge / squash / rebase that doubles as confirmation, last method first) and Ready for review write to GitHub directly through `Cloud/GitHubPullRequests` (`merge` pins the head SHA it just read; `ready` runs GraphQL `markPullRequestReadyForReview`) with the Lody Cloud brokered write grant; never retried, a lost response is reported as unknown. The runtime catalog projects `workspaceDirty`, `workspaceUnpushed` and PR `merge`. Goal and schedule stay on web.
- Agent turns follow web's folding (`ChatTranscript.entryRows`): a running turn (or one that ended without an answer) keeps prose and DSH thoughts inline, but folds each consecutive tool-call run into a command/file/search count summary (`think` steps hidden); opening the summary shows single-line, tail-truncated tool rows, under the live "Working for …" row; once an answer ends it (`answerRun`, the final contiguous text run before the never-folded tail) the work folds into "Worked for … ›", which opens it in place (`LodyChatView.expandedWork` → `ChatTranscript.expandedWork`; the chevron turns on a spring, the tapped row anchors the layout (`toggleAnchor`) while bottom-follow pauses, and rows come and go through the diffable snapshot). Only builtin DSH keeps thoughts (`LodyChatView.showsThoughts`); other providers' thoughts and `think` steps are dropped before the transcript. No warning orange anywhere in a conversation (`chromeColor`, duration rows carry no attention). A turn closes with its output card — the tasks row (`hangSubagents`) and the changed-files row (`changesHeader`, group first/last/only), both drawn by `configureOutputRow` (leading symbol or live spinner, title, detail, trailing, disclosure), each opening its own near full-screen sheet (`TasksController`, `TurnFilesController` → file diff pushed inside the sheet) — and then the meta line, always last.
- Chat process, summary and sub-agent rows use Home's rail glyphs and tree lines; answer text uses the full width with 16 pt margins. File changes form one grouped `lodyInset` block, and code blocks use `lodyInset` fill. The composer is outside the design language rail scope.

- Navigating native list rows retain selection until the owning controller returns. Deselect alongside the navigation transition and restore selection when an interactive return is cancelled; ordinary action rows deselect immediately. Diffable snapshots preserve selection themselves; never reselect a captured row in snapshot completion, which can run after return-time deselection.

## Pages and native APIs

- `LodyShell` owns the root navigation controller and sheet navigation controllers. `LodyPageController` hosts native content, carries results and clears callbacks on close. Reuse `pushNative`, `presentNative`, `finish` and `close`; do not add a second presentation manager.
- Deep links are parsed by `LodyCore.AppLink` and routed by `LodyApplication`. Notification navigation validates account, workspace and session catalog before opening a session.
- `HomeController` owns the adaptive UIKit split and list, session and inspector navigation controllers. Preserve system back and interactive pop. `SessionNavigation` handles session actions; tool pages use `LodyShell.presentDetail`. Keep sheets for transient flows and Debug demos.
- Register page factories in `Shell/LodyNativePages.swift`. Controllers read Swift-owned state and observe NotificationCenter changes. Inject service closures for I/O; offline preview subclasses use scripted services. Use `String(localized:bundle:)` with `.lody` and edit `packages/LodyKit/Sources/LodyKit/Resources/Localizable.xcstrings` directly. Use Foundation format arguments and catalog plural variations; `InfoPlist.xcstrings` owns permission prompts.
- Pages write bar items to the hosting `LodyPageController.navigationItem`. Bottom toolbars appear only while their page is top; item updates wait for the running transition. Remove observers when their owner goes away; UIKit work runs on the main actor.
- `LodyFormController` editors use inline-label `LodyFormRow` rows in hairline-separated `LodyFormGroup` groups on `lodyGround`.
- `pnpm test` checks cloud protocol and verification tooling. Use Node 22 LTS (22.13+) for TypeScript stripping and module mocks. `pnpm verify:native` checks native behavior; `swift test --package-path packages/lody-core` checks routing and protocol policy.

- Keep fault injection, runtime internals, and navigation/native demos on the development-only Debug page, reached from Settings. Product screens expose actionable connection state only.

## Cloud POC

- Device Flow uses the currently registered `lody-cli` client transparently; do not claim a dedicated iOS client until the server registers one. Never substitute desktop credentials for app authorization.
- `data-runtime` in LodyKit owns the POC's catalog replicas, Streams reads, cursors and retry. Native sessions observe projected catalog events; do not add a second live replica. The old offline decoder is retained only as a comparison path.
- Swift owns the offscreen WebView and watchdog. Keep startup/heartbeat deadlines outside JS, ignore callbacks from replaced views, and bound automatic restarts. Background suspension is not a watchdog failure: retain the WebView and reset its heartbeat deadline on foreground; recreate only a missing or failed runtime. User-started sends use only a short UIApplication background allowance through reply synchronization; never request BGContinuedProcessingTask, which displays a system Live Activity, or use idle connection keepalive.
- The host↔runtime boundary is the versioned contract in `packages/cloud-runtime/src/contract`, with generated Swift in `packages/lody-core` (`pnpm contract`). Add methods there: the runtime exposes only `dataRuntime.receive` and posts only `ready` / `envelope`; do not add `callAsyncJavaScript` commands.
- Only short-lived workspace Streams grants enter the bundled WebView; long-lived Better Auth credentials stay in Keychain. Never load remote scripts or expose tokens in diagnostics. Logout and unsubscribe must stop the owned runtime.
- This POC reads catalogs and session history, and sends text turns. CRDT replicas restore from server bootstrap. App account/workspace context and complete catalog display projections restore from SQLite in LodyKit before background authentication and sync; credentials remain in Keychain. Loro/Flock updates use uint32 big-endian length frames; never append raw WASM exports. Persist the user history before the durable dispatch pointer and Machine RPC. A machine ACK is delivery, not completion. Never automatically replay writes across runtime recovery. Catalogs have an explicit 16 MiB per-replica input ceiling; do not label an incomplete or failed sync as live.
- Generate native runtime assets before prebuild/build. Preserve dependency licenses beside generated resources. Native watchdog behavior has a deterministic Swift check in `verification/kit/watchdog`.

- Model capabilities are per agent config (ACP provider), as web (`['acpCapability', configId]`): `creationOptions` keys them by config and carries `agentConfigId`; look them up with `CreateLogic.capability(in:machineId:configId:...)` (new session by `agent.id`, a session by catalog `agentConfigId`), falling back to agent type only for legacy rows. Never match by agent type alone, or one provider shows another's models.
- `ChatComposerView` in LodyKit owns the shared native input, draft handoff/restore, and model controls. Chat embeds it directly. The new-session form is native (`CreateSession/CreateSessionController`) and is shared by the app sheet (`LodyCreateSessionView`) and the Share Extension; it places the composer on the keyboard layout guide, so do not add a second keyboard avoidance owner. On iPhone it is pushed full screen over Home like web (`params.pushed`, back button; the shell page hides its header because the form owns a navigation bar for its pickers); iPad and shared content keep the sheet. Its root page follows web's mobile new-chat page (checked by driving its Storybook stories): `CreateSession/CreateSessionContext` (SwiftUI, hosted by the controller) shows computer and project as plain full-width lines (no fills: the page reads as Liquid Glass composer + content) whose options expand in place right below them, aligned with the line (no indent) and with no surface of their own; computers carry their OS (catalog `machineOs` from machine meta `os`) and show the matching SF Symbol (Mac laptop / iMac / mini / Studio / Pro by name, `pc` for Windows, `server.rack` for Linux); the panel is bottom-anchored, so a list fades in place (`.blurReplace`) while the layout rises, never sliding against it (web's inline picker: one open at a time; computers without an online assistant listed but disabled; the project list searches every usable project and leads with No project, the five most recent projects usable on that computer, then More projects… which pushes the picker), then the worktree chip for local projects (`useWorktree` through the draft record into the runtime's local project ref) or the GitHub branch line expanding inline with search. The assistant is not on the page. The composer runs in `cardStyle` (the Liquid Glass surface, kept a rounded card while typing instead of morphing into the keyboard sheet; one text line at rest and three while editing, growing on a spring with the keyboard; no @ button, as web (typing @ still opens mentions); +, @, the run-config chip `mark  model · effort · mode`, send; placeholder "Work with <assistant>"); the chip opens `CreateRunConfigSheet` (Agent when there is a choice, Model, Reasoning, Mode rows expanding in place; no Plan / Fast on new sessions). The Share Extension compiles these files directly, so it links `LodyDesignSystem` and includes `CreateSessionContext.swift` (`apps/ios/project.yml`). The UI verification cases that tapped the old Project / Chat tabs (`create-parity`, `devices`, `home`) need updating to the context rows. New-session drafts carry text and attachments together into the first turn, including native restoration when upload fails.

- New-session options persist in `LocalStore` under versioned account/workspace/project keys. Restore the complete provider/capability projection before runtime refresh; cached options can populate pickers but cannot authorize Send. Refresh failures retain the cached list, and successful reads replace it. Generation fencing prevents an in-flight read from repopulating storage after logout.
- An open creation page refreshes from catalog/presence events, without polling. Unknown presence retains cached choices. The selected online provider may request missing capabilities through machine RPC; skip binary-progress frames and apply only the final response matching workspace, machine, config and provider identity to the local display projection.

## Share Extension

- `LodyShare` is declared in `project.yml` and compiles listed LodyKit sources by reference, guarded by `LODY_SHARE_EXTENSION`. It never runs the WebView, data runtime or network, and never reads Keychain.
- The app writes a credential-free App Group snapshot (`ShareStore`: catalog, cached options, prefs). Send writes an inbox entry and opens `lody://share/<id>`; `NativeShareCoordinator` drains entries into the ordinary outbox, and falls back to the pre-filled form when the selection is unresolved or stale. The link only wakes the drain.

## UI regression verification

- UI Verify runs only in English (`en`, `en_US`), retaining light/dark coverage. Do not run a separate Chinese locale pass.
- UI Verify establishes the English software keyboard and offline environment once per runner batch; cases reuse that baseline. Enter Debug fixtures through `UI.open_case` deep links, never by scrolling the Debug menu. Batch text input; use individual software keys only when the key interaction is itself under test. Record entry/check timings and prefer observable readiness over fixed sleeps.
- On native UIKit pages use `axe drag`, not `swipe`; swipe doesn't drive UIKit pan gestures (switch thumbs, edge back).

- UI baselines must run without login, user credentials, cloud access, or a connected machine. Add independently resettable Debug scenes using production controllers and `LodyShell.presentNative`; inject deterministic data/service outcomes at their boundary.
- UI changes must add/update a behavior check in `apps/ios/verification/ui` or reuse the existing native checks. Shared controls must be exercised in each affected host.
- Local checks omit `--udid` to lease a `Lody * Verify` Simulator. Build with `pnpm verify:build` (one shared Xcode DerivedData per checkout; never pass a per-task `-derivedDataPath` or copy the checkout into the temp directory, and reclaim such leftovers with `pnpm verify:clean`). Wrap build + multi-check flows with `pnpm verify:simulator --name '<current verify>' -- <command>` and use `$LODY_VERIFY_UDID`; never call `simctl create` directly. Explicit `--udid` is for caller-owned devices such as CI. See `apps/ios/verification/ui/README.md`.
- Capture screenshots for visual states and video for temporal behavior. Missing scenes/timeouts fail verification; screenshots alone do not establish visual correctness.

## Push notifications

- Native OneSignal SDK ownership stays in LodyKit `Notifications/PushNotifications.swift`;
  `PushLifecycle` initializes at app launch, retains SDK listeners and caches
  clicks until `LodyApplication` resolves and acknowledges them.
- `project.yml` and `App` persist the NSE, App Group,
  SDK pin and entitlements across prebuild. Never fix only generated `ios/` files.
- Notification navigation accepts only the legacy workspace/session route and resolves
  against the signed-in user's catalog. `recipientUserId` fences clicks after an
  account switch; old payloads use the SDK's current external ID as a compatibility fallback.
- Debug's offline notification fixture never initializes OneSignal or requests real
  permission. See `apps/ios/PUSH_NOTIFICATIONS.md` for setup and verification limits.

- New-session GitHub branches restore a credential-free SQLite projection keyed by account, workspace and repository, then refresh page 1 in the background. Refresh replaces the cached page set; pagination appends only to the fresh set. Failed refreshes retain the cached list and can retry page 1. Explicit branch choices are remembered per repository in the scoped creation preferences and are never overwritten by a refresh. Cache writes use the creation service's store generation so logout fences late responses.

- The compact new-chat permission face uses a neutral shield for agent/default (a mobile override of web); unknown modes are hidden, read-only/edit/plan use icons, full-access modes use the warning shield, and auto uses the short `Auto` label. Full permission names stay in the picker and accessibility label.

- Conversation members use native `AuthAPI.members` pagination and the account/workspace-scoped `WorkspaceMembers` SQLite projection (ID, name, HTTPS avatar URL only). Cached identities render first; fresh responses reconfigure message rows without waiting for new messages. Request cancellation, account/workspace ownership, credential equality and LocalStore generation fence stale results and logout writes. Failed refreshes retain cached identities.

- The conversation header has no PR button or historical PR menu. PR navigation stays in the context capsule above the composer.

- Conversation changed files never expand inline: the files row keeps file count and line totals and opens `TurnFilesController` (titled with the file count). Keep the tasks row, files row and final model/time footer ordering when changing this output card.
