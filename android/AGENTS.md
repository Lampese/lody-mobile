# Lody Android

- Independent Android-only client. Use Kotlin and Gradle Kotlin DSL; open the root in Android Studio.
- The iOS repository is a reference for behavior and public cloud protocol only. Do not import its build, private packages, credentials, or absolute source paths.
- UI decision: use Jetpack Compose + Foundation, with Material 3 components where appropriate. Keep product components and design tokens separate from screens. iOS and Android share design semantics and component responsibilities, but keep platform-native navigation, keyboard, accessibility and lifecycle behavior. No extra UI component library by default.
- Runtime decision: initially host the same browser cloud runtime in a native-owned WebView. Business code depends on a platform-neutral Kotlin interface; WebView, JSON bridging and watchdog internals remain inside the implementation. Preserve command/event semantics across Swift and Kotlin so a future native runtime can replace the WebView implementation.
- Keep watchdog deadlines outside JavaScript, fence callbacks by runtime generation, bound automatic restarts, suspend deadlines in background, and never replay writes after recovery. Long-lived credentials stay native; only short-lived grants may enter the runtime. A machine ACK is delivery, not completion.
- Phase 2 adds independent Device Flow and a read-only workspace catalog probe. Offline diagnostics remain separate. Creation now exposes only typed creation options and a single create-and-send command; diagnostics and fault injection belong only in the debug source set.
- The vendored cloud-runtime source is an unchanged, provenance-tracked snapshot of `../ios/packages/cloud-runtime` (`docs/runtime-snapshot.md`). Bridge code lives in `runtime/src`; when Android needs a protocol field, add it to the iOS runtime and re-snapshot instead of patching the snapshot at bundle time. Retain dependency licenses and reproducible asset generation.
- Use stable dependency versions, pinned in `gradle/libs.versions.toml`; AGP owns built-in Kotlin support. AGP 9 ships Kotlin 2.2, so the root `buildscript` puts the catalog's newer Kotlin Gradle plugin (2.4) on the classpath; the Compose compiler plugin follows the same `kotlin` version.
- Preserve user edits. Never copy tokens or signing keys into the repository. Keep local SDK paths in ignored `local.properties`.
- Follow native Android navigation, lifecycle, accessibility, and background execution rules.
- Verify scaffold changes with `./gradlew :app:assembleDebug :app:lintDebug`. Add behavioral tests when implementing behavior; do not report NO-SOURCE tasks as passing tests.

## Phase 1 runtime contract

- `LodyApplication` owns `RuntimeOwner`; pages never create or destroy a runtime. Tie foreground/background to ProcessLifecycleOwner, not Activity callbacks. Every operation supplies its expected account/workspace scope; switching/logout cancels the old lease and observers.
- Features depend on the suspend/StateFlow `CloudRuntime` contract. Keep JSON, WebView and callback transport inside the adapter. Debug-only commands and fixture scopes stay under `src/debug`.
- Negotiate protocol/capabilities before READY. Keep native control/query/diagnostic deadlines and bounded chunk assembly; coroutine cancellation removes native waiters and cooperatively aborts JS. Cancellation is not rollback. No replay across recovery or process restart.
- Run JS, JVM owner/protocol tests and Android WebView tests for runtime changes. Snapshot drift checks are part of asset generation; update hashes and provenance only after reviewing an intentional source update. See `docs/runtime-snapshot.md`.

## Phase 2 auth and network boundaries

- AccountController owns native credentials and serializes login/restore/cancel/logout. Public UI state contains no device_code or bearer token. Use the official registered lody-cli Device Flow client until the server provisions a dedicated Android client.
- Keystore stores the AES-GCM key; only ciphertext goes to noBackupFilesDir. Invalidated keys or tampered ciphertext require fresh login. Never import desktop credentials or log tokens/server bodies.
- Avatars are display data: `Account.image` / `Workspace.image` come from `get-session` `user.image` / `organization/list` `logo`, HTTPS only (`httpsImage`), persisted with the account context. `home/AvatarImages` is the one exception to fixed endpoints: an unauthenticated HTTPS image GET (no credentials or cookies, same-protocol redirects only, 2 MiB cap, downsampled, in-memory cache); a failure keeps the monogram.
- Native HTTP uses fixed official endpoints, bounded bodies, cancellation and no redirects/cookies/logging. NetworkRuntime is a local bundled asset whose CSP permits only the validated grant origin. Fetch and native interception both restrict requests to the selected workspace: catalog/session reads, meta appends, session create/append, dispatch RPC request append and response create/read. Reject redirects, remote scripts, deletes and machine-catalog writes.
- The cloud runtime starts with the verified native account identity and watches machine presence; offline probes still omit identity. Network readiness and catalog synchronization are separate states; a WebView heartbeat never means cloud LIVE.
- Keep one app module and manual construction while these boundaries remain small. JSON belongs in adapters; do not introduce a second Streams client in native code or a dependency-injection framework for this probe.

## Catalog cache and connection recovery

- `CatalogRepository` replaces the old cloud probe controller and owns the selected workspace, one runtime subscription and the typed display projection. Pages observe its StateFlow; they never own a WebView or parse cache JSON.
- `CatalogStore` / `AccountContextStore` are suspend ports. The current AtomicFile implementation stores bounded whole snapshots under noBackupFilesDir; a future database implementation can replace it when queries require it. No credentials, CRDT replicas, cursors or send intents belong in this cache.
- Cached account/workspace context is unverified. Grant requests require online account validation. Login switching, logout and credential revocation cancel owned work before clearing projections. Network failures retain cached display, never label it LIVE.
- Only a matching catalog + synced event pair may persist. Stamp `RuntimeEmission.generation` at native receipt before buffering; never infer the origin generation at collection time. Revisions restart per generation.
- Persist with a scope-owned conflated worker; disk latency must not backpressure cloud event delivery. Cancel and join the worker before clearing/switching its scope.
- RuntimeLifecycle owns one process-lifetime network subscription. Network validation is a recovery hint for an unavailable read lease, not proof of cloud liveness; backgrounding never registers another callback or starts recovery work.

- Creation options share the atomic cache lifecycle: persist all providers and model/mode/effort choices by account + workspace + project target, restore before refresh, retain on read failure, and enable Send only after live validation. Options files are separately bounded to 16 snapshots and cleared with account cache on logout.

## Home UI

- `home/HomeActivity` is the launcher: sign-in (Device Flow) without an account, otherwise `home/ChatListScreen`, which opens `chat/ChatScreen` for a row. It reads `AccountController` / `CatalogRepository` state only and picks the first workspace when none is restored.
- Layout matches iOS Home: Chats tab has the workspace capsule (logo + name) leading, search and the view menu trailing, and `HomeSyncPill` floating centred over the bar for syncing / offline / briefly connected (web `MobileConnectionStatus`); search takes over the bar and hides the capsule. A floating bar holds labelled Chats / Projects / Settings tabs plus a separate new-chat button. Projects opens a project's chats in place; Settings shows account, workspace switching and sign-out.
- The view menu scopes Chats to My tasks (catalog session `userId` equals the signed-in user; `HomeScope`, SharedPreferences, default team; search is unscoped). Chats follow the view menu's single grouping choice (`HomeGrouping`, SharedPreferences, default time) via `ChatListModel.home`: time buckets (last message, else `createdAt`), projects by latest activity (rows drop the project from line 2), or status (`StatusGroup`, web `lib/home-now.ts` order: needs you / just finished / running / open PRs / idle; idle folds after 20). Within a group chats are newest activity first; there is no separate sort. Search stays by time. Outside search, Compose `stickyHeader` keeps a single accessible group label under the app bar; the next group pushes it off. Headers use the page colour without blur or a separate overlay. Search labels scroll normally. Rows mirror iOS: status mark (web order failed > waiting > working > unread: alert, hand, `LodyWorkingGrid`, dot), title and compact age; an optional second line with repo / folder + project, branch and the PR mark trailing (a PR mark alone stays on line 1, before the age; open / draft PRs carry the web CI verdict badge); the status mark centres on the whole row. Opened chats nest one level under their root opener within each group (`ChatListModel.nest`, mirroring iOS `SessionRows.tree`; contained Tabs keep their own row), as on iOS: the opener row stays like any other (its own project / branch line); below it the family line `⌄ 7 opened chats` (`FamilyToggle`, count from `ChatItem.childCount`, full-width target, chevron at the opener's title edge, turning right when folded; `FoldedOpeners`, default unfolded; `ChatListModel.fold`) heads the family. Children read one size down (callout, 40 dp rows), keep the shared status column, and hang off one continuous 2 dp rail under the chevron (`drawRail`, round end on the last child) with titles stepped in `TreeLevel`. Children hide a project that repeats their opener's. A folded opener's status shows its family's most urgent. The view menu is a multi-select of those details (`ChatRowDetails`, SharedPreferences, default project + PR); none leaves rows one line. Optional catalog fields (repo, branch, read / message / awaiting times, PRs) are parsed leniently in `runtime/CatalogJson` so older caches still load. `ChatListModel.groups` (pinned, projects by name, unassigned last) feeds the Projects tab. Keep the model pure and covered by `ChatListModelTest`.
- UI uses the shared mobile design system in `../design-system` (Gradle adds `generated/android`, `runtime/android` and `fonts` as source / res dirs): `LodyTheme`, semantic tokens, Inter, Lucide `LodyIcons`. Do not hard-code colors, sizes or fonts in screens.
- Every user-visible string lives in `res/values/strings.xml` with a matching `res/values-b+zh+Hans/strings.xml` entry; keep both key sets identical.
- New chat opens `create/CreateSessionScreen` full screen, kept in step with iOS: computer and project as plain full-width lines (no fills) whose options expand in place right below them, aligned with the line (one open at a time; the bottom-anchored panel reveals a list from its top edge so it moves with the layout; project list: No project, five recent, More projects…, search over all), computers with OS icons (`CreateSessionModel.machineKind` from catalog `machineOs`), then the worktree chip (local) or the typed branch line (GitHub), then the composer on a floating overlay surface (+, run-config chip `model · effort · mode` opening a label/value sheet whose rows expand in place, send; no @; one line at rest, three while editing). When the iOS create page changes, change this page in the same change. Creation reads online assistants and advertised models/reasoning/modes through `CreateSessionRepository` using the existing scope lease. GitHub branches use native authenticated Cloud token brokerage followed by bounded GitHub reads; tokens never enter Compose or the WebView. AccountController fences results across logout. The branch picker restores a cached list and selection by account/workspace/repository, refreshes page 1 in the background, and appends further pages on demand. Explicit choices survive refresh, failures retain cached choices, and a computer change does not reset the branch. AtomicCatalogStore retains at most 16 branch snapshots (1 MiB each), clears them with account data and prunes removed workspace access. Keep empty-assistant guidance out of the page; the configuration chip and disabled send state express availability. Send creates the session stream and catalog metadata, ensures the session replica, then uses upstream text-turn persistence and dispatch; a machine ACK is delivery only. Stable session/turn IDs and the attempted state prevent automatic replay after timeouts, suspension or rotation. Unknown results offer opening the conversation, never an automatic resend. Attachments and mentions remain unavailable. `CreateSessionModel` is pure and covered by `CreateSessionModelTest`. `CreationJson` owns JSON; UI never handles bridge objects.

## Conversation

- `chat/ChatScreen` follows web's mobile session page as it runs in the app: a floating header (round back button, title, GitHub repo line) over the transcript, which scrolls beneath it; user turns are large rounded right-aligned bubbles with the delivery mark (web `UserMessageSendStatus`: open circle sent, check read, clock queued), time and sender name above and a 36 dp avatar beside the bubble's top; agent turns carry no identity and open with the process line ("Finished working", or the working grid while streaming); a round scroll-to-latest button appears once the reader scrolls up; the composer is a bordered card (+, agent mark + model, send). `TranscriptMargin` is 16 dp. Above the composer, `ChatActionBar` is web's `SessionInfoBar` with native menus: computer chip (OS icon, menu names it), context chip (PR / branch, CI verdict, ±diff; menu opens the PR URL or copies the branch) and the repository actions as one accent split button (top action sends on tap with a confirm haptic; the chevron menu holds the rest). `SessionInfoBar` (pure, `SessionInfoBarTest`) ports `resolveSessionInfoBarGitHubActionIds` (Commit & Push first on unpublished work; Create PR / Draft without a PR; Resolve Conflicts on merge state `d`; Fix CI on `f`/`e`; Ready for review on a draft; Merge when GitHub reports clean and CI passed or is absent, kept in the menu behind Commit & Push; nothing while busy) and web's localized prompts, sent through the ordinary turn path only while still offered. Merge (after `MergeSheet`, a bottom sheet of merge / squash / rebase that doubles as confirmation, last method first) and Ready for review write to GitHub directly: `GitHubPullRequestWrites` gets a Lody Cloud brokered write grant (`getOperationAccessTokenByRepoNameForClient`, operation write) under `AccountController.withVerifiedAccount`, merges with the head SHA it just read (409 = head moved) or runs GraphQL `markPullRequestReadyForReview`; never retried, and a lost response is reported as unknown. Goal and schedule stay on web. The catalog carries `diff`, `workspaceDirty`, `workspaceUnpushed` and PR `url` / `merge`. Senders other than the signed-in user show as Member until the member list is loaded.
- Sending is live (no read-only label): `ChatRepository.send` runs the `sendText` runtime command (Android adapter over upstream `sendTurn`) with a fresh stable turn id; running sessions queue. An optimistic bubble shows until the transcript carries the turn id; `not_sent` marks it failed, an uncertain result stays sent, and nothing is resent automatically. The catalog supplies the session's machine, cliType, agentType and resume; the session entry summary carries `userId`.

## Chat transcript (spike)

- `chat/` holds the transcript pipeline, mirroring iOS `ChatMarkdownRepair` / `ChatMarkdownStore`: coalesce chunks per frame (`renderMarkdown`), repair while streaming only, split into top-level blocks with the JetBrains GFM parser, render each block as its own lazy item (`ChatTranscript`, `MarkdownBlock`). The original text stays the source of truth; repaired text is display-only.
- Repair runs the shared `../shared/markdown-repair/entry.js` (remend, pinned in `runtime/package.json` to the iOS version) as the `markdown/MarkdownRepair.js` asset in QuickJS (`QuickJsMarkdownRepair`, quickjs-kt, which serializes evaluations itself). Every failure returns the input unchanged. Do not route repair through the WebView runtime. Unit tests run the real engine via `quickjs-kt-jvm` against the built asset (`markdown.repair` system property).
- Renderer: mikepenz multiplatform-markdown-renderer. Its append-only streaming state does not fit remend output (closing markers move), so blocks re-render with `retainState = true` instead; without it a growing block flashes back to loading.
- `diagnostics/ChatStreamProbeActivity` (debug) replays `assets/chat/fixture.md` as a token stream and reports repair / split cost and long frames, with repair and coalescing toggles.

- The compact new-chat permission face uses a neutral shield for agent/default (a mobile override of web); unknown modes are hidden, read-only/edit/plan use icons, full-access modes use the warning shield, and auto uses the short `Auto` label. Full permission names stay in the picker and accessibility label.
